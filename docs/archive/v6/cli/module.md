OWASP Top 10 testing  - API endpoint discovery  - Authentication bypass attempts  - Session management analysisDependencies:  - recon (must be enabled first)  - vuln (shares vulnerability database)Configuration Options:  - max-depth: Maximum crawl depth (default: 3)  - timeout: Request timeout in seconds (default: 30)  - user-agent: Custom User-Agent string  - cookies: Custom cookies to send with requests  - headers: Custom HTTP headers  - proxy: Proxy server for outgoing requests```## Common Options| Option | Description ||--------|-------------|| `--yaml` | Output in YAML format instead of table || `--json` | Output in JSON format || `--quiet` | Suppress informational messages |## Typical Workflow1. **List Modules**: See what modules are available and their current status2. **Select Modules**: Enable only the modules needed for your assessment3. **Configure Options**: Adjust module-specific settings if required4. **Run Scan**: Execute the scan with your selected modules5. **Review Results**: Analyze findings from the enabled modules6. **Adjust as Needed**: Modify module selection based on initial results## Related Commands- `hunterx scan` - Execute a scan with selected modules- `hunterx config` - View and modify global configuration settings- `hunterx workflow` - Create workflows that use specific module combinations## Common Errors- **Unknown Module**: Ensure the module name is spelled correctly and exists- **Dependency Missing**: Some modules require others to be enabled first (check module info)- **Configuration Invalid**: Verify that any custom options are valid for the module## Best Practices- Start with a minimal set of modules and add more as needed- Regularly review and update your module selection based on assessment requirements- Consult module documentation for specific configuration options- Disable invasive modules (like exploit) when performing compliance assessments- Keep modules updated to ensure coverage of the latest threats
