Learn how to perform  network and vulnerability scans with various modules and options.---# Scan CommandThe `scan` command is the primary entry point for conducting security assessments with HunterX. It orchestrates reconnaissance, vulnerability scanning, and optional exploitation based on the selected modules and configuration.## Syntax```bashhunterx scan [OPTIONS] TARGET```## Arguments| Argument | Description ||----------|-------------|| `TARGET` | The target to scan (hostname, IP address, CIDR range, or URL) |## Options| Option | Description ||--------|-------------|| `-m, --modules <list>` | Comma-separated list of modules to run (e.g., `recon,vuln,exploit`) || `-o, --output <format>` | Output format (json, yaml, txt, html) || `--output-dir <path>` | Directory to save output files || `--timeout <seconds>` | Timeout for each scan phase (default: 300) || `--retries <count>` | Number of retry attempts for failed operations (default: 3) || `--threads <count>` | Number of concurrent threads (default: 10) || `--rate-limit <rate>` | Maximum requests per second (default: 0 for no limit) || `--safe` | Enable safe mode (disable exploitation attempts) || `--stealth` | Use stealth techniques to evade detection || `--no-confirm` | Skip confirmation prompts || `--resume <session-id>` | Resume a previous scan session || `--schedule <cron>` | Schedule the scan to run at specified intervals || `--notify <method>` | Notification method upon completion (email, slack, webhook) || `--tags <list>` | Tags to apply to the scan results for categorization || `--exclude <list>` | Comma-separated list of IPs or hosts to exclude from scanning || `--include <list>` | Comma-separated list of IPs or hosts to force-include in scanning |## Examples### Basic Network Scan```bashhunterx scan 192.168.1.0/24```This performs a basic reconnaissance and vulnerability scan on the entire subnet.### Web Application Scan```bashhunterx scan --modules recon,vuln web.example.com```Focuses on web-specific reconnaissance and vulnerability checks.### Stealth Scan with Custom Output```bashhunterx scan --stealth --output json --output-dir ./results 10.0.0.5```Performs a stealthy scan and saves results as JSON in the specified directory.### Scheduled Scan```bashhunterx scan --schedule "0 2 * * *" --email admin@example.com example.com```Runs a scan every day at 2 AM and emails the results.## Expected OutputThe scan command outputs progress information to the terminal and saves detailed results to the specified output directory. By default, results are saved in `./scans/<timestamp>/`.The output includes:- Reconnaissance results (open ports, services, technologies)- Vulnerability findings (CVSS scores, affected components)- Exploitation results (if applicable and successful)- Risk assessment and remediation recommendations## Typical Workflow1. **Target Identification**: Determine the target(s) to scan (IP range, domain, etc.)2. **Module Selection**: Choose appropriate modules based on assessment goals3. **Scan Execution**: Run the scan with desired options4. **Result Analysis**: Review findings and prioritize remediation5. **Reporting**: Generate reports for stakeholders6. **Remediation**: Address identified vulnerabilities7. **Rescan**: Verify that vulnerabilities have been resolved## Related Commands- `hunterx module` - Manage and list available scan modules- `hunterx agent` - Control autonomous agents during scans- `hunterx workflow` - Define and execute custom scanning workflows- `hunterx report` - Generate reports from scan results## Common Errors- **Target Not Reachable**: Ensure the target is online and accessible from your network- **Permission Denied**: Run with appropriate privileges (may require root/administrator for certain scans)- **Module Not Found**: Verify the module name is correct and installed- **Timeout Exceeded**: Increase the timeout value for slow or unreliable targets## Best Practices- Always obtain proper authorization before scanning any target- Start with a reconnaissance-only scan to understand the target- Use safe mode initially to avoid unintended disruption- Regularly update modules and vulnerability databases- Document your scanning methodology and findings
