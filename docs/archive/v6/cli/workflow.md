Workflows allow you to define repeatable assessment processes that combine multiple HunterX components into a single, coordinated operation.## Syntax```bashhunterx workflow [SUBCOMMAND] [OPTIONS]```## Subcommands| Subcommand | Description ||------------|-------------|| `list` | List all available workflows || `create` | Create a new workflow from a template or scratch || `run` | Execute a workflow || `edit` | Modify an existing workflow || `delete` | Remove a workflow || `export` | Export a workflow to a file || `import` | Import a workflow from a file || `validate` | Check a workflow for errors |## Examples### List Workflows```bashhunterx workflow list```Sample output:```Available Workflows:  quick-scan       : Fast external assessment  full-assessment  : Comprehensive security evaluation  web-app-test     : Focused web application testing  compliance-check : PCI DSS / HIPAA compliance verification  incident-response: Automated intrusion investigation```### Create a New Workflow```bashhunterx workflow create --name "internal-pentest" --template "full-assessment"```### Run a Workflow```bashhunterx workflow run "compliance-check"```### Export a Workflow```bashhunterx workflow export "web-app-test" --output "my-workflow.yaml"```### Import a Workflow```bashhunterx workflow import --input "custom-workflow.yaml"```## Workflow StructureWorkflows are defined in YAML format and consist of:1. **Metadata**: Name, description, version, author2. **Parameters**: Input variables that can be customized at runtime3. **Stages**: Sequential or parallel execution phases4. **Steps**: Individual actions within each stage (scans, module operations, agent commands)5. **Conditions**: Logic for branching based on results6. **Output**: Specification of what to save and how to format it### Simple Workflow Example```yamlname: "Basic Network Scan"description: "Perform reconnaissance followed by vulnerability scanning"parameters:  target:    description: "Target network or host"    type: "string"    required: truestages:  - name: "Reconnaissance"    steps:      - agent.deploy:          name: "recon"          target: "{{ parameters.target }}"          mode: "passive"      - module.enable:          names: ["recon", "vuln"]  - name: "Assessment"    steps:      - scan.execute:          target: "{{ parameters.target }}"          profile: "standard"      - report.generate:          format: "html"          output: "./reports/{{ parameters.target }}_report.html"```## Common Options| Option | Description ||--------|-------------|| `--format` | Specify output format (yaml, json) || `--validate` | Validate workflow before execution || `--dry-run` | Show what would be executed without running || `--verbose` | Show detailed execution steps || `--timeout` | Set maximum execution time in minutes |## Typical Workflow Creation Process1. **Define Objective**: Clearly state what the workflow should accomplish2. **Identify Components**: Determine which modules, agents, and scans are needed3. **Structure Stages**: Break the objective into logical phases4. **Define Steps**: Specify exact actions for each stage5. **Add Parameters**: Make the workflow reusable with different inputs6. **Test and Refine**: Run the workflow in a test environment and adjust7. **Document**: Add clear descriptions and usage instructions## Related Commands- `hunterx scan` - Execute individual scans that can be part of workflows- `hunterx agent` - Control agents that workflows may deploy- `hunterx module` - Manage modules that workflows may enable/disable- `hunterx report` - Generate reports that workflows may produce- `hunterx reasoning` - Configure AI decision-making used in advanced workflows## Common Errors- **Invalid Syntax**: YAML formatting errors in workflow definition- **Missing Reference**: Referencing a non-existent module, agent, or scan type- **Circular Dependency**: Creating workflows that depend on themselves indirectly- **Resource Conflict**: Attempting to use the same port or resource in parallel steps- **Permission Denied**: Lacking required privileges for certain operations## Best Practices- Start with simple workflows and gradually add complexity- Use parameters to make workflows reusable across different targets and scenarios- Include error handling and validation steps in complex workflows- Document each step clearly for team collaboration and knowledge transfer- Version control your workflows using Git or similar systems- Test workflows in isolated environments before production use- Regularly review and update workflows to incorporate new modules and techniques- Leverage existing workflow templates as starting points for customization
