Configure scan behavior, agent behavior, reporting preferences, and more.---# Config CommandThe `config` command allows you to view, edit, and manage HunterX configuration settings.Configuration controls various aspects of HunterX behavior including scan parameters,agent behavior, reporting preferences, and integration settings.## Syntax```bashhunterx config [SUBCOMMAND] [OPTIONS]```## Subcommands| Subcommand | Description ||------------|-------------|| `list` | List all configuration options with current values || `get` | Get the value of a specific configuration option || `set` | Set the value of a specific configuration option || `reset` | Reset configuration options to default values || `export` | Export current configuration to a file || `import` | Import configuration from a file || `reset-all` | Reset all configuration to factory defaults |## Examples### List All Configuration Options```bashhunterx config list```Sample output:```Configuration Options:  scan.timeout              : 300 (seconds) - Timeout for each scan phase  scan.threads              : 10 - Number of concurrent threads  scan.rate-limit           : 0 (requests/sec) - Rate limiting (0 = no limit)  scan.safe-mode            : false - Disable exploitation attempts  agent.max-concurrent      : 5 - Maximum concurrent agents  agent.timeout             : 30 (minutes) - Agent execution timeout  report.default-format     : html - Default report format  report.output-dir         : ./reports - Default output directory  knowledge-graph.enabled   : true - Enable knowledge graph storage  knowledge-graph.host      : localhost - Knowledge graph database host  knowledge-graph.port      : 7687 - Knowledge graph database port  update.check-interval     : 24 (hours) - How often to check for updates  update.channel            : stable - Update channel (stable, beta, dev)  logging.level             : info - Logging level (debug, info, warn, error)  logging.file              : ./logs/hunterx.log - Log file path  logging.console           : true - Enable console logging```### Get a Specific Configuration Value```bashhunterx config get scan.timeout```Output:```scan.timeout: 300```### Set a Configuration Value```bashhunterx config set scan.timeout 600```### Set Multiple Configuration Values```bashhunterx config set scan.threads 20 scan.rate-limit 10```### Reset Configuration to Defaults```bashhunterx config reset scan.timeout scan.threads```### Export Configuration```bashhunterx config export --output ./my-hunterx-config.yaml```### Import Configuration```bashhunterx config import --input ./my-hunterx-config.yaml```### Reset All Configuration to Factory Defaults```bashhunterx config reset-all```## Configuration Categories| Category | Description ||----------|-------------|| **Scan** | Scan timeout, threads, rate limiting, safety options || **Agent** | Agent concurrency, timeouts, behavior settings || **Report** | Default formats, output directories, template preferences || **Knowledge Graph** | Database connection, storage options, synchronization || **Update** | Check frequency, update channels, backup settings || **Logging** | Log levels, file output, console output, format || **Network** | Proxy settings, DNS resolution, timeout values || **Security** | SSL verification, authentication tokens, encryption settings |## Common Options| Option | Description ||--------|-------------|| `--format` | Output format (yaml, json, txt) || `--quiet` | Suppress informational messages || `--verbose` | Show detailed information || `--file` | Specify configuration file (default: ./config/hunterx.yaml) || `--reset` | Reset to default after getting/setting (for testing) |## Configuration FileHunterX stores its configuration in YAML format by default at:```./config/hunterx.yaml```Example configuration file:```yamlscan:  timeout: 300  threads: 10  rate-limit: 0  safe-mode: falseagent:  max-concurrent: 5  timeout: 30report:  default-format: html  output-dir: ./reportsknowledge-graph:  enabled: true  host: localhost  port: 7687update:  check-interval: 24  channel: stablelogging:  level: info  file: ./logs/hunterx.log  console: true```## Typical Workflow1. **View Configuration**: Use `hunterx config list` to see current settings2. **Identify Changes**: Determine which settings need adjustment for your use case3. **Modify Settings**: Use `hunterx config set` to adjust specific values4. **Verify Changes**: Use `hunterx config get` to confirm new values5. **Persist Changes**: Configuration is automatically saved to the config file6. **Backup/Share**: Export configuration for backup or sharing with team members7. **Reset if Needed**: Use `hunterx config reset` or `reset-all` to revert to defaults## Related Commands- `hunterx scan` - Scan behavior is affected by scan-related configuration- `hunterx agent` - Agent behavior is affected by agent-related configuration- `hunterx report` - Report generation is affected by report-related configuration- `hunterx update` - Update behavior is affected by update-related configuration- `hunterx doctor` - Diagnostic checks may examine configuration settings## Common Errors- **Invalid Option Name**: Ensure the configuration option name is correct and exists- **Invalid Value Type**: Verify the value matches the expected type (integer, boolean, string, etc.)- **Value Out of Range**: Numeric values must be within acceptable ranges (e.g., timeout > 0)- **Configuration File Not Found**: The configuration file is locked or inaccessible- **Invalid Format**: When importing, ensure the file is valid YAML or JSON- **Permission Denied**: Insufficient permissions to read/write the configuration file## Best Practices- Make configuration changes incrementally and test after each change- Document non-standard configurations for team reference- Use environment-specific configuration files for different deployment scenarios- Regularly review and update configuration as your use cases evolve- Backup your configuration before making significant changes- Use version control for configuration files to track changes over time- Consider using environment variables for sensitive settings (API keys, passwords)- Test configuration changes in a development environment before production use
