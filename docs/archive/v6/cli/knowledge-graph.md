HunterX'\''s knowledge graph, which serves as a centralized repository for storing and correlating security data collected during assessments.## Syntax```bashhunterx knowledge-graph [SUBCOMMAND] [OPTIONS]```## Subcommands| Subcommand | Description ||------------|-------------|| `status` | Check the status of the knowledge graph database || `stats` | View statistics about stored data || `clear` | Remove all data from the knowledge graph || `import` | Import data from external sources (scans, reports, etc.) || `export` | Export knowledge graph data to external formats || `query` | Execute a custom query against the knowledge graph || `visualize` | Generate a visual representation of the graph || `backup` | Create a backup of the knowledge graph || `restore` | Restore the knowledge graph from a backup || `optimize` | Optimize the database for better performance || `nodes` | List, add, or remove nodes (assets, vulnerabilities, etc.) || `edges` | List, add, or remove edges (relationships between nodes) || `labels` | Manage node and edge labels (types, classifications) |## Examples### Check Knowledge Graph Status```bashhunterx knowledge-graph status```Sample output:```Knowledge Graph Status:  Database: Neo4j Community 4.4.5  Status: Online  Nodes: 1,247  Edges: 3,891  Labels: 12 (Asset, Vulnerability, Service, Credential, etc.)  Relationship Types: 8 (HOSTS_SERVICE, HAS_VULNERABILITY, etc.)  Size on Disk: 45.2 MB  Last Backup: 2023-08-20 14:30:00```### View Statistics```bashhunterx knowledge-graph stats```Sample output:```Knowledge Graph Statistics:  Node Counts:    Asset: 89    Vulnerability: 156    Service: 203    Credential: 42    Domain: 23    IP Address: 145    Port: 312    Web Application: 34    Database Instance: 12    Cloud Resource: 18    Container: 26  Edge Counts:    HOSTS_SERVICE: 412    HAS_VULNERABILITY: 287    CONNECTS_TO: 195    COMMUNICATES_WITH: 156    STORES_DATA_IN: 89    PROCESSES_DATA: 67    AUTHENTICATES_TO: 34    LOCATED_IN: 78  Graph Density: 0.12  Average Node Degree: 6.2```### Import Scan Results```bashhunterx knowledge-graph import --input ./scans/20230815_143022/ --format json```### Export to CSV```bashhunterx knowledge-graph export --format csv --output ./kg-export/```### Query the Knowledge Graph```bashhunterx knowledge-graph query --cypher "MATCH (a:Asset)-[:HOSTS_SERVICE]->(s:Service)-[:HAS_VULNERABILITY]->(v:Vulnerability)WHERE v.severity = \"CRITICAL\"RETURN a.name AS asset, s.name AS service, v.name AS vulnerability, v.cvss AS scoreORDER BY v.cvss DESCLIMIT 10"```### Visualize the Graph```bashhunterx knowledge-graph visualize --output ./kg-visual.png --format png```### Backup the Knowledge Graph```bashhunterx knowledge-graph backup --output ./backups/kg-backup-20230820.db```### Add a Node Manually```bashhunterx knowledge-graph nodes add \  --label Asset \  --name "web01.example.com" \  --properties "{ \"type\": \"web_server\", \"os\": \"Linux\", \"ip\": \"192.168.1.10\" }"```### Create a Relationship```bashhunterx knowledge-graph edges add \  --from "Asset:web01.example.com" \  --to "Vulnerability:CVE-2021-3156" \  --type HAS_VULNERABILITY \  --properties "{ \"evidence\": \"sudo version 1.8.31\", \"confidence\": 0.95 }"```## Common Options| Option | Description ||--------|-------------|| `--format` | Output format (json, yaml, csv, txt) || `--output` | Specify output file or directory || `--quiet` | Suppress informational messages || `--limit` | Limit number of results returned (for queries) || `--offset` | Skip a number of results (for pagination) || `--order` | Sort results by specified field(s) || `--filter` | Apply filters to query results (key=value) |## Typical Workflow1. **Initialize**: Ensure the knowledge graph is running and accessible2. **Import Data**: Bring in scan results, reports, or other security data3. **Explore**: Use stats and queries to understand what data is present4. **Analyze**: Run complex queries to correlate data and identify patterns5. **Visualize**: Generate graphs to communicate findings to stakeholders6. **Export**: Share data with other tools or team members7. **Backup**: Regularly backup the knowledge graph to prevent data loss8. **Maintain**: Periodically optimize and clear old data as needed## Related Commands- `hunterx scan` - Generate data that can be imported into the knowledge graph- `hunterx report` - Create reports that may include knowledge graph insights- `hunterx reasoning` - Use the knowledge graph as a data source for AI analysis- `hunterx agent` - Agents may read from and write to the knowledge graph during operations- `hunterx workflow` - Workflows can automate knowledge graph import/export tasks## Common Errors- **Database Not Running**: Ensure the knowledge graph service is started- **Connection Refused**: Verify the database is listening on the expected port and host- **Authentication Failed**: Check credentials if the database requires authentication- **Invalid Query Syntax**: Ensure Cypher queries are properly formatted- **Insufficient Permissions**: Verify you have read/write access to the database files- **Disk Space Exceeded**: Free up space or archive old data before importing large datasets## Best Practices- Regularly backup the knowledge graph, especially before large imports- Use meaningful labels and properties to make data easily queryable- Periodically clean up old or irrelevant data to maintain performance- Leverage the knowledge graph for trend analysis across multiple assessments- Combine automated data import with manual curation for highest quality- Document your knowledge graph schema and conventions for team consistency- Use visualization to communicate complex relationships to non-technical stakeholders- Schedule regular optimization tasks to maintain query performance- Consider encrypting backups if storing sensitive information
