Check system health, dependencies, and configuration integrity.---# Doctor CommandThe `doctor` command performs comprehensive diagnostic checks on your HunterX installation to identify and help resolve issues related to installation, configuration, dependencies, and system compatibility.## Syntax```bashhunterx doctor [SUBCOMMAND] [OPTIONS]```## Subcommands| Subcommand | Description ||------------|-------------|| `run` | Run all diagnostic checks || `list` | List available diagnostic checks || `info` | Show detailed information about a specific check || `fix` | Attempt to automatically fix detected issues || `report` | Generate a detailed diagnostic report || `schedule` | Schedule regular diagnostic checks || `history` | View history of diagnostic runs |## Examples### Run All Diagnostic Checks```bashhunterx doctor run```Sample output:```HunterX Diagnostic Report========================Timestamp: 2023-08-20 14:30:00Overall Status: HEALTHY (8 checks passed, 1 warning, 0 failures)System Information:  OS: Windows 10 Pro 10.0.19045  Architecture: x64  Python: 3.9.7  HunterX Version: v6.0.0Checks Performed:  [PASS] Python Version Check  [PASS] Required Dependencies  [PASS] HunterX Installation Integrity  [PASS] Configuration File Validity  [PASS] Knowledge Graph Connectivity  [PASS] Module Library Access  [WARN] Optional Dependency: Graphviz not found (visualization features limited)  [PASS] Network Connectivity to Update Servers  [PASS] Disk Space Availability  [PASS] Memory Availability  [PASS] File Permissions  [PASS] Environment VariablesRecommendations:  1. knowledge-graph,dependencies```## Diagnostic CategoriesDiagnostic checks are organized into categories:### System Compatibility- Python version- Operating system compatibility- Architecture (32-bit vs 64-bit)### Dependencies- Required Python packages- Optional enhancements- External service requirements### Installation Integrity- File existence and permissions- Version consistency- Installation completeness### Configuration- Configuration file syntax- Required settings presence- Value validity and ranges### Connectivity- Network access to external services- Update server availability- Knowledge graph database access- API endpoint accessibility### Resources- Disk space availability- Memory availability- CPU capacity- File descriptor limits### Permissions- File and directory access rights- Privilege requirements for specific operations- Service account permissions## Common Options| Option | Description ||--------|-------------|| `--checks` | Specify which checks to run (comma-separated list) || `--exclude` | Exclude specific checks from execution || `--severity` | Minimum severity level to report (info, warn, fail) || `--format` | Output format (text, json, xml, html, markdown) || `--output` | Output file path for results || `--quiet` | Suppress informational output, show only warnings and errors || `--verbose` | Show detailed output for each check || `--fix-attempts` | Number of automatic fix attempts to make (default: 1) || `--timeout` | Timeout in seconds for each check (default: 30) || `--no-color` | Disable colored output || `--ignore-cache` | Ignore cached results and run fresh checks |## Typical Workflow1. **Initial Assessment**: Run `hunterx doctor run` to get overall system health2. **Investigate Issues**: Examine any warnings or failures in detail3. **Research Solutions**: Use `hunterx doctor info` to understand specific issues4. **Apply Fixes**: Use `hunterx doctor fix` for automated fixes or follow manual recommendations5. **Verify Fixes**: Re-run diagnostics to confirm issues are resolved6. **Schedule Monitoring**: Set up regular checks to catch issues early7. **Review History**: Use `hunterx doctor history` to track system health over time## Related Commands- `hunterx update` - Keep HunterX current to avoid known issues- `hunterx config` - View and modify configuration settings- `hunterx info` - Display basic HunterX version and build information- `hunterx agent` - Check agent-specific health and status- `hunterx module` - Verify module availability and integrity- `hunterx knowledge-graph` - Diagnose knowledge graph-specific issues## Common Errors- **Permission Denied**: Lack of sufficient privileges to access files or services- **Connection Refused**: Unable to connect to required services (databases, APIs)- **Missing Dependencies**: Required packages not installed or wrong versions- **Configuration Invalid**: Syntax errors or invalid values in configuration files- **Resource Exhaustion**: Insufficient memory, disk space, or file descriptors- **Environment Issues**: Missing or incorrect environment variables- **Service Unavailable**: Required external services are offline or unreachable- **Timeout Exceeded**: Check took longer than allowed time to complete## Best Practices- Run diagnostics regularly as part of maintenance routine- Address warnings promptly to prevent them from becoming failures- Keep baseline diagnostic reports for comparison during troubleshooting- Document any manual fixes applied for future reference- Use the fix function cautiously and review what changes will be made- Schedule diagnostics during off-peak hours to minimize performance impact- Combine doctor checks with logging for comprehensive troubleshooting- Create custom checks for organization-specific requirements if needed- Share diagnostic reports with support teams when seeking assistance- Include doctor output in bug reports for more effective troubleshooting
